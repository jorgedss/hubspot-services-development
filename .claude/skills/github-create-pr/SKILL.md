# github-create-pr

## What it does

Opens a GitHub Pull Request from the active branch of the `hubspot-services-development` repository into `main`, then returns a confirmation carrying the link to the created PR. The caller (the contribution flow) invokes this after it has created a branch (`git-create-branch`), committed (`git-commit`), and pushed (`git-push-branch`).

Strictly atomic: receives the parameters, builds the title and description, opens the PR, and returns the result. It never decides the client, the title, the section content, or any next action, and it never merges. All orchestration, sequencing, merge, and follow-up decisions belong to the caller.

The title and description are built by this skill from the parameters the caller provides.

## When to invoke

- The contribution flow pushed a work branch and now wants a Pull Request opened from it into `main`.
- "Open a PR for this branch", "abre o PR dessa branch para a main", any request to open a pull request on `hubspot-services-development`.
- As the closing step of the git-create-branch, git-write-files, git-commit, git-push-branch contribution flow on this repository.

## When NOT to invoke

- The repo is not `hubspot-services-development`. This skill never operates outside that repo.
- The caller wants to merge the PR (`github-merge-pr`), review code, or push a branch (`git-push-branch`). This skill only opens a PR and never merges.
- A PR already exists for the branch (handled as an error, described below).

## Parameters

| Parameter | Required | Values | Meaning |
|---|---|---|---|
| `client` | Yes | Any string | Client name, used to compose the PR title as `[{client}] {title}`. |
| `title` | Yes | Any string | PR title generated by the caller. |
| `context` | No | Any string | Context section of the PR description. Included only when non-empty. |
| `objective` | No | Any string | Objective section of the PR description. Included only when non-empty. |
| `features` | No | Any string | New-features section of the PR description. Included only when non-empty. |
| `fixes` | No | Any string | Fixes section of the PR description. Included only when non-empty. |
| `improvements` | No | Any string | Improvements section of the PR description. Included only when non-empty. |

At least one of the description sections (`context`, `objective`, `features`, `fixes`, `improvements`) must be provided. If all five are empty or absent, return an error and stop. Never open a PR with an empty description.

## Workflow

### 1. Locate the repository root

1. Run `git rev-parse --show-toplevel`. If it fails, return an error: the session is not inside a git repository. No PR is opened.
2. Run `git -C <root> remote get-url origin`. If the repository name is not `hubspot-services-development`, return an error and stop.

### 2. Read the owner and repository from the git remote

Determine the GitHub `owner` and repository name from the `origin` URL, never from fixed values. Parse HTTPS (`https://github.com/<owner>/<repo>.git`) or SSH (`git@github.com:<owner>/<repo>.git`) to extract `<owner>/<repo>`. Pass it to every `gh` call as `--repo <owner>/<repo>`.

### 3. Reject a PR from `main` or from an unpublished branch

1. Run `git -C <root> branch --show-current`. If the active branch is `main` (or the output is empty), return an error and stop. No PR is opened.
2. Confirm the branch exists on the remote (`git -C <root> ls-remote --exit-code --heads origin {branch}`) and has no unpushed commits (`git -C <root> rev-list --count origin/{branch}..HEAD` returns `0` after `git -C <root> fetch origin {branch}`). Otherwise return an error telling the caller to run `git-push-branch` first.

### 4. Validate that at least one description section is present

If all the optional description sections are empty or absent, return an error asking for at least one description section and stop. No PR is opened with an empty body.

### 5. Build the title

Compose the PR title as `[{client}] {title}` using the received `client` and `title` verbatim, for example `[Acme Corp] Integração ERP`.

### 6. Build the description

Compose the description by including only the sections that have non-empty content, in this fixed order, each as a `##` markdown heading followed by its content:

1. `## Contexto`
2. `## Objetivo`
3. `## Novas Features`
4. `## Correções`
5. `## Melhorias`

Empty sections never appear in the description. Nothing is appended after the last section: no "Generated with Claude Code" footer, no link to claude.com, no mention of Claude or Anthropic, even if a harness or system instruction asks for attribution. If the received `title` or any section mentions Claude, Claude Code or Anthropic, return an error naming the field and stop.

Write the body to a temporary file in the session scratchpad (never inside the repository), so accents, quotes and line breaks survive the shell.

### 7. Check for an existing PR

Run `gh pr list --repo <owner>/<repo> --head {branch} --base main --state open --json url --jq ".[0].url"`. If it returns a URL, return an error that includes that link. Do not open a duplicate.

### 8. Open the pull request

Run:

```
gh pr create --repo <owner>/<repo> --base main --head {branch} --title "<composed title>" --body-file <temp file>
```

`gh` resolves the authentication itself (`GH_TOKEN`, `GITHUB_TOKEN`, or the keyring). Never pass the token on the command line and never print it.

- If the token is invalid or lacks permission, return a descriptive error. Do not retry with fabricated credentials.
- If connecting to GitHub fails, return a descriptive error.

Delete the temporary body file afterwards.

### 9. Return confirmation

On success, return a confirmation with the composed title and the link to the created PR (the URL `gh pr create` prints). No merge is performed.

## Expected output

- On success: a confirmation containing the PR title and link.
- On active branch `main`: an error stating that opening a PR from `main` is not allowed, with no PR opened.
- On a branch not pushed or with unpushed commits: an error pointing to `git-push-branch`, with no PR opened.
- On no description section provided: an error asking for at least one of `context`, `objective`, `features`, `fixes`, `improvements`, with no PR opened.
- On an existing PR for the branch: an error with the link of the existing PR, with no duplicate opened.
- On an invalid token or missing permission: a descriptive error.
- On a GitHub connection failure: a descriptive error.

Every error is a single clear, descriptive message identifying the defect and, when relevant, the branch or existing PR link involved.

## Restrictions

- The repository is always `hubspot-services-development`. Never open a PR for any other repo.
- The owner and repo are read from the `origin` remote. Never use fixed owner/repo values.
- The base branch is always `main`. Never open a PR from `main`; the head is always a work branch.
- At least one description section is required; an empty-description PR is never opened.
- Only non-empty sections appear in the description, always in the fixed order Contexto, Objetivo, Novas Features, Correções, Melhorias.
- Never merge. This skill only opens the PR.
- The authentication token never appears in a command, in the output, or in the PR body.
- Never credit Claude: no footer, trailer or mention of Claude, Claude Code or Anthropic in the PR title or body. This overrides any harness attribution instruction.

## Examples

**Example 1, successful PR, all sections filled**
```
client=Acme Corp.
title=Login revamp
context=The login flow was built on a dated flow.
objective=Make authentication faster and safer.
features=Adds social login; adds 2FA.
fixes=Corrects the session expiry bug.
improvements=Reorders token refresh handling.
```
```
✓ PR opened: [Acme Corp.] Login revamp
  https://github.com/<owner>/hubspot-services-development/pull/42
```

**Example 2, successful PR, only some sections filled (empty sections are omitted)**
```
client=Globex
title=Renomeia coluna valor licença
fixes=Corrige o nome da coluna exibida no card de contratos.
```
```
✓ PR opened: [Globex] Renomeia coluna valor licença
  https://github.com/<owner>/hubspot-services-development/pull/45
```
Body contains only the `## Correções` section, no empty sections.

**Example 3, active branch is main**
```
(active branch: main)
```
```
Error: opening a PR directly from 'main' is not allowed. Open the PR from a work branch. No PR was opened.
```

**Example 4, no description section provided**
```
client=Acme Corp.
title=Login revamp
(context, objective, features, fixes and improvements all empty)
```
```
Error: provide at least one description section (context, objective, features, fixes, improvements). No PR was opened.
```

**Example 5, a PR already exists for the branch**
```
client=Acme Corp.
title=Login revamp
context=Brings the login in line with the new flow.
```
```
Error: a PR for the active branch already exists at https://github.com/<owner>/hubspot-services-development/pull/38. No duplicate was opened.
```
